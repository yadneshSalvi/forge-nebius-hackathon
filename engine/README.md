# Local contact-physics adapter

This adapter runs MuJoCo 3.3.7 on the local CPU. Its original Cartesian gantry has three actuated slide coordinates and two actuated fingers. The payload and protected block are free rigid bodies. Position actuators, contact constraints and friction lift and release the payload; there is no weld, mocap attachment, object teleport, or outcome override. Static rails and pillars identify the simplified gantry fixture; their collision masks are disabled and exported as such. This is a simulation module, with no robot hardware, Isaac, GR00T, CUDA, or vision-policy qualification.

`spec.py` is the registered task. `task_spec()` returns its canonical SHA-256. The task uses SI units, a right-handed z-up world, and WXYZ quaternions. The four factors, nuisance distribution, held-out composition embargoes, predicates, thresholds and finite minimization neighborhood are part of that hash. The task was piloted and frozen before search. Different nuisance seeds vary reset, observation and control conditions. Repeating an identical seed measures repeatability rather than independent probability.

```python
from engine import nominal_scenario, bootstrap_base, run_episode, audit_episode

base = bootstrap_base("data/base")
episode = run_episode(nominal_scenario(42), base["checkpoint"], trace=True)
assert audit_episode(episode)["valid"]
```

The policy observes eight instrumented quantities: measured protected-block height, estimated friction, payload yaw, tray offset, measured pick x/y, and tray x/y. The NumPy network is 8→24→16→2, with tanh hidden layers. It predicts palm lift height and finger closure position, above a fixed nine-phase smooth position controller. The expert labels those same two targets and executes them through the same contact physics and task oracle. A demonstration must include the completed expert episode and bind its scenario, observations, labels and oracle exactly to that episode. Failed expert attempts remain acquisition evidence and never become successful labels. Sealed, confirmation, validation and challenge episodes, and both embargoed compositions, are rejected for training.

Base training acquires 40 successful authored expert episodes from the declared narrow distribution, with at most 120 attempts. Every attempt is written to `base-acquisition-attempts.jsonl`. Training updates 650 parameters by backpropagation and Adam for 1,000 steps. Adaptation defaults to 600 updates, 24 independent bootstrap draws with replacement per update, and learning rate 0.004. The registered comparison uses 24 successful demonstrations per arm: eight retained nominal and 16 corrective. Optimization seeds are 101, 202, 303, 404 and 505, each starting from the same saved base. The control service owns arm acquisition and evaluation; this module does not select a final evaluation winner.

`train_policy(demos, base_checkpoint, seed, budget, policy_id)` returns an actual learned checkpoint with tensor lists, loss curve, initial/final weight hashes, exact demo lineage, parent hash and resource measurements. `save_policy`/`load_policy` use bounded JSON, verify the content hash and tensor/normalization schema, and never load pickle. File SHA-256 and canonical checkpoint SHA-256 are separately reported. The whole checkpoint includes measured elapsed time, so deterministic training is checked through tensor hashes and outputs, not byte-identical checkpoint files.

`run_episode(scenario, policy, trace=True, cancel_callback=None)` returns JSON. `trace=False` retains initial/final body poses and physics-step oracle aggregates; it deliberately omits dense data for bulk runs. `trace=True` records 25 Hz authoritative frames and 500 Hz qpos/qvel, actuator commands and grouped contact forces. `physics.protected_contact_points` additionally retains each individual non-table protected-object contact, including forces below the 0.10 N threshold. This permits reconstruction of forbidden steps, point count, peak force and impulse. Raw qpos contains both free-body positions and WXYZ quaternions; frames also export oriented corners and world body velocities. Geometry positions/quaternions are body-local and dimensions are half extents. `world` is an identity body. Browser interpolation is presentation only.

Raw state rows contain each solver's pre-integration state and one final state. Contact indices refer to that pre-integration state. This avoids confusing MuJoCo's updated `qpos` with derived body transforms from the previous step. Free-joint angular velocities in raw qvel are body-local; frame angular velocities are transformed to world coordinates. See the primary [MuJoCo API](https://mujoco.readthedocs.io/en/stable/APIreference/APIfunctions.html) and [free-joint conventions](https://mujoco.readthedocs.io/en/3.5.0/overview.html).

`episode_evidence_hash` covers every raw episode field except `evidence_hash` and measured `timing`. API decoration must be stored outside this envelope. `audit_episode` verifies integrity and reconstructs the geometry/contact oracle from dense traces. It is a consistency checker; an independent reviewer should still inspect the exported task, raw geometry and contacts. A partial canceled attempt has status `interrupted`, success `null`, and is excluded from task-failure denominators.

`render_episode(episode, path, time_index=None, width=960, height=640)` restores a recorded qpos in the matching MuJoCo scene, forwards kinematics and renders a real image. `time_index` is a frame index; the default selects the frame closest to 4.2 seconds. On macOS, create the renderer on the process main thread. Rendering does not rerun an episode or change its verdict.

Run `python -m pytest tests/test_engine.py -q` in the pinned environment. Tests cover oriented containment, units/polarity, free-body contact transport, bounded reset and held-out rejection, deterministic nuisance draws, actual learned tensors, five optimization seeds, checkpoint/demo tampering, cancellation and dense-trace reconstruction. Observed pilot outcomes are development evidence, not sealed benchmark or hardware results.
